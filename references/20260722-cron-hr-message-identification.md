# Cron HR消息识别启发式（2026-07-22 验证）

## 问题

从 `document.body.innerText` 读取聊天页全文本后，如何程序化地区分 HR 主动发来的消息 vs 自己发送的消息？

## 启发式

根据 `extract-detail`（即 `document.body.innerText`）的输出格式：

### HR 主动发来的消息
- **无前缀**标记
- 格式：`"HH:MM\nHR姓名公司名职位\n消息内容"`
- 例如：`"14:17\n<HR>女士COMPANY_3hr\nhello现在是离职状态吗？"`

### 自己发送的消息
- 带有 `[已读]` 或 `[送达]` 前缀
- 格式：`"[已读]\n消息内容"` 或 `"[送达]\n消息内容"`
- 例如：`"[已读]\n这是我的作品集，百度网盘链接：..."`

### 系统拒绝通知
- 无 `[已读]/[送达]` 前缀
- 但内容包含"不够匹配"、"不符合要求"、"不合适"等关键词
- 不属于需回复的HR消息

### 其他注意事项
- HR主动消息中可能包含：问离职状态、问机会、约面试、问技能、要简历
- 群发广告通常不含具体提问意图（如酒店住宿、保姆陪跑、无责保底）
- 短剧/AIGC方向按用户规则"最后考虑"

## 验证

2026-07-22 cron运行验证：
1. 导航到 `/web/geek/chat`
2. 点击「全部」标签（「未读」标签显示"30天内暂无联系人"）
3. 用 `extract-detail` 读取全页文本
4. 按上述启发式过滤出 HR 消息
5. 成功识别<HR>女士（问离职状态）→ 已回复

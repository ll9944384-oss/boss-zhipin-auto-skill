# 2026-07-23: Unified Feed View Analysis

## 观察

BOSS直聘聊天页 `/web/geek/chat` 显示为**统一时间线 feed**，
而非传统的"左侧对话列表 + 右侧单独聊天面板"布局。

### 页面结构

```
┌────────────────────────────────────────────────────┐
│  导航栏 (首页 职位 公司 校园 ... 消息 简历 YOUR_NAME)     │
├────────────────────────────────────────────────────┤
│  全部 │ 未读 │ 新招呼 │ 仅沟通 │ 更多               │  ← 过滤标签
├────────────────────────────────────────────────────┤
│  01:27                                              │
│  <HR>女士COMPANY_4hr                                    │
│  [送达]                                              │
│  你好~ 目前正在看新的机会...                            │  ← 所有对话混排
│                                                     │
│  昨天                                                │
│  <HR>女士COMPANY_2招聘者                          │
│  你好，在推荐里面看到你的简历...                        │
│                                                     │
│  07月21日                                            │
│  <HR>女士COMPANY_7HRBP                            │
│  老师～我们太需要你这样优秀的人才啦~                     │
│  ...                                                │
│                                                     │
│  滚动加载更多                                        │
└────────────────────────────────────────────────────┘
```

### 关键特征

1. **所有对话按时间倒序排列**在同一个内容区域中
2. **每条消息有明确的归属**：HR 名称 + 消息内容
3. **自己发送的消息**带 `[已读]` 或 `[送达]` 标记，在HR名称行之后
4. **HR 主动发送的消息**无 `[已读]/[送达]` 标记
5. **右侧没有独立的聊天面板**（`hasChatInput` 始终为 `false`）

### 好处

- 可以通过 `document.body.innerText` 一次性获取所有对话内容
- 无需先"打开"某个对话 — 所有消息都在页面上可见
- 文本解析足够可靠：按时间戳行拆分即可获取每条消息

### 局限性

- 无法直接发送回复（需要打开具体对话，但Vue事件屏障阻止）
- 如果对话还未打开过，无法通过程序化方式发送消息
- 只能读取/分析，不能直接回复

### 提取策略

```python
from safari_boss_runner import json_js

# 获取页面全部文本
result = json_js('return document.body.innerText;')
full_text = result.get('result', '')

# 区分HR消息 vs 自己发送的消息
# HR消息: "时间\nHR名称\n消息内容" (无 [已读]/[送达])
# 自己发送: "时间\n对方名称\n[已读]/[送达]\n消息内容"
```

### 对话列表LI项（左侧侧边栏）

Safari 渲染的侧边栏 LI 元素也有结构化的 rect 信息可用：

```python
# 提取所有 LI 对话项的坐标和文本
js = '''
var items = document.querySelectorAll('li');
var result = [];
for (var i = 0; i < items.length; i++) {
  var li = items[i];
  var r = li.getBoundingClientRect();
  if (r.width > 50 && r.height > 20) {
    result.push({
      idx: i,
      text: (li.innerText || '').trim().slice(0, 200),
      rect: {left: r.left, top: r.top, width: r.width, height: r.height}
    });
  }
}
return JSON.stringify(result);
'''
raw = safari_js(js)
```

### HR消息分类规则（统一feed适用）

消息在统一feed中的格式决定了分类方式：

```
格式1: "昨天\n<HR>女士COMPANY_2招聘者\n你好..."  → HR消息（无标记）
格式2: "昨天\n<HR>女士COMPANY_19招聘专员\n[已读]\n这是我的作品集..." → 我方消息
格式3: "昨天\n<HR>女士COMPANY_20招聘专员\n感谢你的关注，暂时与该职位不够匹配..." → 系统拒绝（无标记，但含拒绝关键词）
```

**启发式规则**：
1. 文本行包含 `[已读]` 或 `[送达]` → 我方发送的消息
2. 文本行包含"不够匹配"、"不符合"、"不合适"等 → 系统拒绝，无需回复
3. 其他无标记消息 → HR主动消息，需进一步判断相关性与回复策略
